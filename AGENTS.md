# OpenROAD-flow-scripts (ORFS) — Agent Context

See `README.md` for the general ORFS guide and `ML_EXTENSIONS.md` for the user-facing ML/UI documentation.

The OpenROAD (OR) engine source resides in `tools/OpenROAD/` (git submodule). For C++/Tcl development, refer to `tools/OpenROAD/AGENTS.md`.

---

## Project Overview

This is a fork of OpenROAD-flow-scripts with three additions layered on top:

1. **`flow/ml/`** — ML training pipelines: U-Net congestion prediction and GraphSAGE GNN floorplan suggestion
2. **`flow/ui/`** — Flask web UI replacing terminal commands, with SSE log streaming, ML inference buttons, and an HTML5 Canvas layout viewer
3. **`flow/run_ui.sh`** — launch script for the web UI

Everything in the standard ORFS toolchain runs inside Docker. The ML inference and Flask server run on the host.

## Critical: How docker_shell Works

`util/docker_shell` mounts **`flow/`** as `/work` inside the container. All paths passed to it must use `/work/` not the host path.

```bash
# CORRECT — args are joined with spaces, passed directly
util/docker_shell openroad -python /work/ml/congestion/data_collection/extract_placement.py --odb /work/results/...

# WRONG — bash -c breaks arg passing; bash receives "openroad" as the script to run
util/docker_shell bash -c "openroad -python ..."

# WRONG — host path not visible inside container
util/docker_shell openroad -python /home/user/.../flow/ml/...
```

The ORFS make targets are:
- `synth` → synthesis
- `floorplan` → floorplan
- `place` → placement (through `3_3_place_gp`)
- `cts` → clock tree synthesis
- `grt` → global route (NOT `route_global` — that target does not exist)
- `route` → detailed route
- `finish` → finishing/GDSII
- (bare `make`) → full flow through finish

Always pass `DESIGN_HOME=/work/designs` when running make, and use the Docker-internal config path:
```bash
util/docker_shell make DESIGN_CONFIG=/work/designs/nangate45/gcd/config.mk DESIGN_HOME=/work/designs grt
```

## ODB vs DEF

ORFS checkpoints are stored as **ODB** (OpenROAD Database) binary files, not DEF. DEF files are not generated by default.

- ODB files: `flow/results/<platform>/<nickname>/base/<stage>.odb`
- DEF conversion: `flow/ui/odb_to_def.py` — run via `util/docker_shell openroad -python /work/ui/odb_to_def.py --odb <odb> --out <def>`
- Converted DEFs are cached on disk alongside the ODB; gitignored

The layout viewer in `app.py` auto-converts ODB→DEF on demand when a stage is selected.

## Design Nickname System

The results directory name may differ from the design folder name. Always read `DESIGN_NICKNAME` from `config.mk`:

```
flow/designs/nangate45/black_parrot/config.mk  →  DESIGN_NICKNAME = bp
flow/designs/nangate45/bp_be_top/config.mk     →  DESIGN_NICKNAME = bp_be
flow/designs/nangate45/bp_fe_top/config.mk     →  DESIGN_NICKNAME = bp_fe
```

`layout_parser.get_design_nickname(platform, design, flow_dir)` handles this. Use it everywhere before constructing result/log paths.

## Flask API Endpoints

All endpoints in `flow/ui/app.py`:

| Endpoint | Description |
|---|---|
| `GET /` | Serves `index.html` |
| `GET /api/designs` | Lists all designs with `config.mk` under `flow/designs/` |
| `GET /api/run/<p>/<d>` | SSE: runs full ORFS flow in Docker |
| `GET /api/drc/<p>/<d>` | SSE: runs DRC in Docker |
| `GET /api/congestion/predict/<p>/<d>` | SSE: extracts placement if needed, runs U-Net inference in-process |
| `GET /api/congestion/image/<p>/<d>` | Returns predicted congestion PNG |
| `GET /api/floorplan/suggest/<p>/<d>` | SSE: extracts graph if needed, runs GNN inference in-process |
| `GET /api/floorplan/tcl/<p>/<d>` | Returns generated Tcl placement script |
| `GET /api/layout/stages/<p>/<d>` | Lists available ODB/DEF stages for a design |

SSE streams use `data: <line>\n\n` format. The final message is always `data: [EXIT <code>]\n\n`.

## ML Inference Architecture

Both models are loaded once, cached in `_MODEL_CACHE` (module-level dict in `app.py`), and compiled with `torch.compile`. FP16 is used on CUDA.

```python
# app.py — model loading pattern
_DEVICE = torch.device("cuda" if torch.cuda.is_available() else "cpu")
_MODEL_CACHE: dict = {}

def _load_model(model_class, checkpoint, *args, **kwargs):
    if checkpoint in _MODEL_CACHE:
        return _MODEL_CACHE[checkpoint]
    model = model_class(*args, **kwargs)
    model.load_state_dict(torch.load(checkpoint, map_location=_DEVICE))
    model.to(_DEVICE)
    if _DEVICE.type == "cuda":
        model.half()
    model.eval()
    model = torch.compile(model)  # PyTorch 2.x — JIT compilation
    _MODEL_CACHE[checkpoint] = model
    return model
```

When adding new models: follow the same pattern. Never load a checkpoint inside a request handler directly.

When passing tensors to a FP16 model, cast inputs: `x = x.half()` before `model(x)`. Cast outputs back: `out.float().cpu().numpy()`.

## Model Architectures

### CongestionUNet (`flow/ml/congestion/model/unet.py`)

- **Input:** `(B, 1, H, W)` — normalized cell density grid, default H=W=64
- **Output:** `(B, 10, H, W)` — sigmoid-activated congestion per layer (metal1–metal10), values in [0, 1]
- **Architecture:** 4-level encoder-decoder with skip connections, `base_features=32` (doubles each level)
- **Init:** `CongestionUNet(in_channels=1, out_channels=10)`

### FloorplanGNN (`flow/ml/floorplan/model/gnn.py`)

- **Input:** node features `(N, 6)`, edge_index `(2, E)`, batch `(N,)`, macro_mask `(N,)` bool
- **Output:** `(M, 2)` — sigmoid-activated (x, y) in [0, 1] for each macro node
- **Architecture:** Linear projection → 3× GraphSAGE + LayerNorm → global mean pool context → MLP head
- **Node features (6):** `[area_norm, is_macro, is_seq, is_buf, fanin, fanout]`
- **Init:** `FloorplanGNN()` (all defaults)
- **Requires:** `torch_geometric`

## Layout Parser

`flow/ui/layout_parser.py` parses DEF files for the canvas renderer.

Key functions:
- `get_design_nickname(platform, design, flow_dir)` — reads `DESIGN_NICKNAME` from `config.mk`
- `find_lef_files(platform, flow_dir)` — globs `platforms/<platform>/lef/*.lef`
- `parse_lef_macros(lef_paths)` — returns `{cellName: {w, h, is_macro}}` in microns
- `get_available_stages(platform, design, flow_dir)` — returns list of `{id, label, def_path, odb_path}` dicts
- `parse_def(def_path, macro_sizes, max_routes=60000)` — returns JSON-serializable dict

DEF parser output structure:
```python
{
  'dbUnitsPerMicron': 1000,
  'dieArea': [x1, y1, x2, y2],       # in DBU
  'components': [{'name', 'cell', 'x', 'y', 'w', 'h', 'orient', 'is_macro'}],
  'specialRoutes': [{'layer', 'x1', 'y1', 'x2', 'y2', 'w'}],
  'routes': [{'layer', 'x1', 'y1', 'x2', 'y2', 'w'}],
  'pins': [{'name', 'x', 'y'}],
  'layers': ['metal1', ...],
  'layerColors': {'metal1': '#4488ff', ...},
  'routesTruncated': bool,
}
```

The parser caps signal routes at `max_routes=60000` to avoid sending gigabytes to the browser. `routesTruncated` is set to `True` when this limit is hit.

## Canvas Renderer (index.html)

All layout rendering is in the `<script>` block of `flow/ui/templates/index.html`.

Key coordinate transform:
```javascript
function toScreen(defX, defY) {
    return [(defX - panX) * zoom, canvasH - (defY - panY) * zoom];
}
```
DEF Y increases upward; canvas Y increases downward — hence the flip.

Fit-to-view:
```javascript
function fitView() {
    zoom = Math.min(canvasW / dieW, canvasH / dieH) * 0.95;
    panX = die[0]; panY = die[1];
}
```

**Critical timing pattern:** `resizeCanvas()` must not be called while the canvas panel is hidden (`display:none`), because `clientWidth/clientHeight` return 0. Always defer with `requestAnimationFrame` after making the panel visible:
```javascript
switchTab('layout');
requestAnimationFrame(() => { resizeCanvas(); fitView(); render(); });
```

Visibility thresholds (pixels per DBU):
- Components rendered: `pixPerMicron > 0.02` (where `pixPerMicron = zoom * dbUnitsPerMicron`)
- Signal routes rendered: `pixPerMicron > 0.3`
- Pins rendered: `pixPerMicron > 0.1`
- Cell names rendered: `pixPerMicron > 20`

Zoom increment: `factor = e.deltaY < 0 ? 1.05 : 1/1.05` — keep this small (1.05) or scrolling feels too fast.

## Known Gotchas

**`route_global` is not a valid make target.** Use `grt` instead.

**`bash -c` breaks docker_shell arg passing.** docker_shell joins all its arguments with spaces to form the container command. Wrapping with `bash -c` causes bash to receive `openroad` as the script path rather than executing it. Pass the command directly.

**numpy must be installed on the host.** The extraction scripts inside Docker use OpenROAD's bundled Python; the host-side scripts need a separate `pip3 install numpy`.

**FP16 and BatchNorm don't mix.** `CongestionUNet` uses `BatchNorm2d`, which can produce NaN in FP16 during training. FP16 is safe for inference only (already handled in `_load_model`). Never switch the model to FP16 before training.

**`torch.compile` with GraphSAGE.** The first forward pass after `torch.compile` takes 10–30 s for graph tracing. This is expected and only happens once after the server starts.

```bash
# Start the web UI

# Run a design through the full flow (host terminal)
cd flow
util/docker_shell make DESIGN_CONFIG=/work/designs/nangate45/gcd/config.mk DESIGN_HOME=/work/designs

# Collect congestion training data
bash flow/ml/congestion/data_collection/batch_run.sh

# Train congestion model
cd flow
python3 ml/congestion/model/train.py --data-dir ml/data --checkpoint-dir ml/congestion/model/checkpoints --epochs 50

# Collect floorplan training data
bash flow/ml/floorplan/data_collection/batch_run.sh
```
